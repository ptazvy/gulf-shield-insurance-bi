# Data Dictionary: Source Files (Stage 2)

All files live in `/data`, generated by `data/generate_data.py` (seeded with `SEED = 42`, so re-running reproduces identical data). This mirrors what an insurer's real source extracts would look like before ETL — flat CSVs, one per table, no pre-joining.

## Known data quality characteristics (intentional)

These aren't bugs — they're built in on purpose so Stage 4 (ETL) has real validation work to do, just like a real source system would:

- `gender` and `age_band` are blank for SME/Corporate customers (not applicable to a company)
- `days_to_settle` is null for any claim still in an Open status
- Cancelled policies carry a reduced, short-rated premium rather than zero
- Payment installment counts vary (1, 2, or 4 payments) so payment totals must be aggregated per policy, not assumed 1:1
